# 다음 개선 우선순위

2026-09-22 PR #11의 공간·조명 변경까지 반영한 **실측 결과**를 기준으로 세 가지를 제안한다. 완료된 수정과 이후 실험을 구분하며, 아래 개선은 아직 구현·검증 완료로 표시하지 않는다. 최신 증거와 측정 한계는 [공간 전환 보고서](spatial-transitions.md#실제-검증과-성능), 화면의 발전 과정은 [시각적 구현 이력](visual-history.md)에서 볼 수 있다.

| 우선순위 | 확인한 사실·한계 | 다음 작업 | 완료 판단 기준 |
| --- | --- | --- | --- |
| **1 · 첫 모니터 진입의 남은 한 프레임 분석** | PR #11 최종 첫 하강에서 83.3ms 한 프레임이 남았다. 직전 기준은 66.7ms, 조명 연결 중간 측정은 100ms였다. longtask·shader link는 0, 하부 새 전환과 상승 최장은 16.8ms였다. | 영상 비활성·정적 포스터·실제 영상 재생과 조명 영상 분기를 분리하고 영상 프레임 콜백, CPU trace, 지원되는 GPU timer query로 반복 측정한다. 초기 준비 시간도 동시에 기록한다. | 캐시 상태를 통제한 반복 첫 진입에서 원인 범주가 재현되어야 한다. 수정 후 시각 효과·영상 지연 로드·초기 준비 비용을 함께 비교하고 33.5ms 초과 빈도 감소를 확인한다. |
| **2 · 실제 Safari/iOS와 저사양 기기 검증** | 현재 성능 증거는 Chromium / ANGLE D3D11 / 1440 × 900 / DPR 1이다. 실제 iOS Safari·낮은 성능의 GPU·장시간 발열 상태는 미검증이다. | 실제 기기에서 전체 왕복 스크롤, 영상 자동 재생·실패 복구, 세로·가로 전환, 백그라운드 복귀, 모션 감소와 컨텍스트 복구를 점검한다. | 기기·OS·브라우저·DPR을 기록하고 깨진 전환·누락 모델·멈춘 영상·복귀 실패가 없는지 확인한다. 기기별 최장 간격·품질 변화·메모리 경향을 따로 보고한다. |
| **3 · 겹침 비용과 근접 표면 품질 개선** | PR #11 장치·모니터 겹침에서 최대 209 draw를 기록했다. quality 1.00을 유지했지만 저사양 여유는 미확인이다. 바닥을 통과할 때 파편의 각진 면·감쇠 입자가 눈에 띄고, 물 반사는 512px로 제한된다. | CPU/GPU 병목을 나누고 재질 묶기·장면 밖 갱신 생략·LOD·반사 갱신 주기를 비교한다. 그 여유 안에서 가까운 파편의 실루엣과 수면의 미세 반사를 보강한다. | 같은 시점·카메라·입력에서 나선·O·재질·전환 경계를 보존하고, 가까운 면의 깜박임·팝인 없이 목표 기기의 비용 감소를 확인한다. |

**권장 순서는 1 → 2 → 3**이다. 잔여 프레임의 원인을 확인한 뒤 실제 목표 기기에서 재현되는 부담에 맞춰 비용을 줄이는 편이 좋다. 단순히 모든 입자 수·해상도를 낮추면 데스크톱에서 유지되는 시각 품질까지 손상할 수 있다.

PR #10의 역사 측정에서 최초 하강의 33.5ms 초과 프레임 **8→1**, longtask **5→0**, 전환 중 셰이더 링크 **33→0**, 품질 최솟값 **0.85→1.00**을 확인했다. 이 결과와 PR #11의 수치를 섞어 전체 성능이 계속 개선됐다고 주장하지 않는다. 실제 기기 검증과 GPU 실행 시간 분리는 아직 남아 있다.
