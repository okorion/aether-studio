# 3D 인터랙션 구현 순서와 검증 항목

AETHER의 수정 기록에서 다음 구현에 사용할 결정표와 검사를 추렸다. 회색 모델로 공간·입력을 맞춘 뒤 경계, 영상, 성능과 실패 복구를 확인하는 순서다.

## 좌표·입력·자원의 담당 범위

먼저 좌표와 입력·자원의 책임을 정한다.

| 결정 | 적을 내용 | AETHER에서 사용한 선택 |
| --- | --- | --- |
| 붙어 있는 부품 | 함께 이동·회전할 부모와 로컬 연결점 | 링과 리본은 같은 부모 |
| 이동하는 대상 | 카메라·시선 중심·월드 고정 오브젝트 | 중심과 카메라는 하강, 방과 바닥은 고정 |
| 장면을 결정하는 값 | 실제 스크롤과 정규화 진행률의 변환 | native scroll에서 `progress` 계산 |
| 두 시계 | 스크롤 위치로 정할 구조와 시간으로 재생할 효과 | 본 컬럼·체인은 progress, 영상·빛은 elapsed |
| 입력 소유자 | 궤도, 오브젝트 선택, 입자 반응, UI의 우선순위 | 중간 장면은 궤도만 잠금, 선택·빛은 유지 |
| 전환 경계 | 경계를 계산할 한 모듈과 이를 읽는 재질 | 화면 UV의 사선 경계를 여러 객체가 공유 |
| 캡처 책임 | 굴절·반사 타깃의 생성자, 갱신 조건, 해제자 | 모니터 굴절과 수면 반사의 책임 분리 |
| 품질 경로 | 지원할 기기, 줄일 효과, 실패 시 보여 줄 내용 | GPU·모바일·소프트웨어·WebGL 대체 화면 구분 |

**로컬 좌표**는 부모 안에서의 위치다. **월드 좌표**는 장면 전체의 위치다. **화면 좌표**는 카메라로 투영된 위치다. “커서와 같은 방향으로 움직인다”는 요구는 화면 좌표에 가깝고, “바닥에 붙어 있다”는 요구는 월드 좌표에 가깝다. 먼저 어느 공간의 조건인지 적는다.

접점·입력 가중치·전환 경계는 한 곳에서 계산해 전달한다. 입력은 종류별로 조건을 둔다. AETHER에서는 카메라 회전이 잠긴 구간도 입자 반응을 받는다.

## 최소 구현 순서와 통과 조건

### 1. 회색 모델로 공간과 입력부터 연결

텍스처·영상 없이 링, 기둥, 방, 바닥만 둔다. 월드 좌표와 카메라 위치를 읽을 수 있는 작은 진단값을 준비한다.

- [ ] 붙은 부품이 회전·크기 변경 뒤에도 연결된다.
- [ ] 아래로 이동한 뒤 같은 스크롤 위치로 돌아오면 카메라와 구조가 복원된다.
- [ ] 드래그를 놓아도 각도가 유지되고, 취소·포커스 이탈 뒤 입력이 붙잡히지 않는다.
- [ ] 버튼·링크·대화상자·터치를 배경 카메라가 가로채지 않는다.

느린 휠·빠른 휠·역방향으로 이동하며 기준점 사이의 속도까지 확인한다. [카메라 글](posts/01-camera.md)

### 2. 구조·입자·포인터의 시간을 분리

같은 `progress`에 다른 `elapsed`를 넣어 구조 행렬을 비교한다. 정지해야 할 것이 움직이면 시간 입력이 섞인 곳부터 찾는다. 모니터 영상이 재생된다고 전체 이미지가 달라지는 것은 정상일 수 있다.

- [ ] 같은 progress의 본·체인 행렬은 시간이 달라도 같다.
- [ ] 입자 이동은 조명 변화와 분리해서 확인한다.
- [ ] 입력이 끝난 뒤 정해진 수명 안에 복귀하거나 제거된다.
- [ ] 첫 접촉·큰 포인터 점프·긴 프레임 공백이 가짜 궤적을 만들지 않는다.

입자 수를 늘리기 전에 적은 입자로 방향과 복귀를 확인한다. 흐름을 전부 CPU에서 입자마다 계산할지, 공유 필드와 셰이더로 처리할지는 이 단계에서 선택한다. [입자 글](posts/02-particles.md)

### 3. 장면 한 쌍의 경계를 완성

나가는 장면, 들어오는 장면, 그 사이의 문구·입자가 같은 화면 경계를 읽는지 확인한다. 색뿐 아니라 숨긴 픽셀의 깊이도 검사한다.

- [ ] 경계 위·아래에서 이전 객체가 새어나오지 않는다.
- [ ] 실제 바닥·천장·덮개 접점은 geometry의 월드 범위로 맞는다.
- [ ] 바닥에 가까운 시점과 통과 직후, 역진입에서 차폐가 유지된다.
- [ ] 작은 화면·다른 DPR·저해상도 타깃에서도 경계 위치가 같다.

천장·투명 장식·유리 표면별로 깊이 쓰기와 입력 여부를 정한다. [전환 글](posts/03-transitions.md)

### 4. 캡처와 영상을 붙인 뒤 최초 진입을 측정

재질을 컴파일했다는 사실만으로 실제 자원 준비가 끝났다고 판단하지 않는다. 텍스처 업로드, 첫 디코딩, 렌더 타깃 생성, 중첩 캡처가 따로 남을 수 있다.

- [ ] 새 세션의 첫 진입과 이미 본 장면의 재진입을 따로 측정한다.
- [ ] 굴절 캡처 중 수면 반사가 다시 전체 장면을 그리지 않는지 확인한다.
- [ ] 타깃·viewport·scissor·가시성을 임시 변경한 코드는 실패해도 복원된다.
- [ ] 준비 중 취소·장면 재구성 뒤 오래된 비동기 결과가 새 장면을 건드리지 않는다.

효과를 하나씩 제외하며 지연이 남는지 비교한다. [전환 성능 글](posts/05-performance.md)의 영상 요청·코덱 비교가 이 순서를 따른다.

## 증상별로 먼저 확인할 순서

| 증상 | 확인 순서 |
| --- | --- |
| 붙은 부품이 벌어진다 | 부모 계층 → 로컬 연결점 → 중복 회전·이동 |
| 내려가는 느낌이 없다 | camera와 focus 높이 → 주변의 월드 고정 여부 → 기준점 보간 속도 |
| 드래그 해제 후 정면 복귀 | release의 목표 각도 초기화 → 각속도 감쇠 → 장면 재구성 시 보존값 |
| 잠긴 구간 뒤 시점이 튄다 | 입력 허용과 적용 가중치 → held 취소 → 잠금 중 누적 yaw |
| 입자 색만 바뀐다 | 정점 변위 조건 → scroll delta 의존 → 고정 시계의 alpha coverage |
| 포인터 주변에 빈 원이 생긴다 | 고정 반경 cutoff → 중심 정규화 → 씨드별 영향 폭·접선 |
| 카메라를 돌리면 물체가 사라진다 | near/far·부모 visible → 실제 bounds → 셰이더 변위 범위 → 패스별 컬링 |
| 투명한 물체가 뒤를 가린다 | depthWrite → fragment discard 시점 → 정렬·렌더 순서 |
| 아래층에 위층 부품이 남는다 | 물체가 바닥 아래까지 돌출됐는지 → 실제 카메라 높이 → 위층 그룹 가시성 |
| 전환에서만 길게 멈춘다 | 첫 진입/재진입 분리 → CPU long task → shader link → 영상 첫 프레임 → 캡처 중첩 |
| 정지·재개 뒤 영상이 검다 | 미디어 준비 상태 → 텍스처 소유자 → context 복원 → 실패 후 대체 화면 |

원인 후보가 여러 개면 증상을 재현하는 가장 작은 장면을 만든다. 움직이는 배경을 모두 켠 전체 화면만으로는 위치·조명·깊이 중 무엇이 바뀌었는지 분리하기 어렵다.

## 가시성과 절두체 컬링을 구분

`visible=false`는 그 객체를 장면에서 제외하는 강한 결정이다. **절두체 컬링**은 지금 카메라에 들어오지 않는 객체를 그 패스에서 건너뛰는 판단이다. 메인 카메라에서 안 보이는 물체가 수면의 반사 카메라에서는 보일 수 있다.

따라서 메인 카메라의 컬링 결과를 모든 캡처에 쓸 전역 visible 값으로 바로 바꾸지 않는다. 각 패스의 카메라로 판단하거나, 어느 카메라에서도 내용이 없는 전환 경계처럼 확실한 조건에서만 그룹을 제외한다.

셰이더가 정점을 크게 움직이면 CPU가 아는 bounding sphere와 화면의 실제 형상이 달라질 수 있다. bounds를 실제 변위까지 포함하도록 갱신·확장할지, 해당 객체의 컬링을 끌지 비용과 함께 결정한다. near plane을 가로지르는 bounds는 음수 w로 단순 투영하지 말고 보수적으로 남기는 쪽도 검토한다.

이 항목은 다음 구현의 진단 기준이다. AETHER의 실제 적용 범위는 [성능 글](posts/05-performance.md)에 있다.

## 측정 기록 템플릿

```text
변경 목적 / 가설:
비교 버전(커밋)과 실행 주소:
GPU / OS / 브라우저 / 렌더러:
viewport / DPR / 품질 프로파일:
캐시 / 새 세션 여부 / 영상 준비 상태:
입력 경로(시작·끝·방향·시간·정착 대기):
비교 횟수 / 동시 실행한 작업:

RAF 중앙값 / p95 / 최댓값 / 기준 초과 프레임 수:
GPU 타이머 p95 / disjoint 여부:
CPU long task / shader compile·link:
draw 수 / 추가 캡처 수 / 품질 최솟값:
브라우저 오류 / 영상 실패 / 자원 개수:

확인된 사실:
기각한 가설과 근거:
아직 분리하지 못한 원인:
실제 이미지·원자료 경로와 캡처 조건:
채택 / 추가 측정 / 되돌림 결정:
```

RAF 간격은 콜백 사이의 시간으로 기록한다. GPU 타이머에는 지원 여부와 disjoint 상태를 남긴다. 정착 후 2초와 첫 20초 스크롤은 구간 이름을 나눠 보관한다.

버전끼리 같은 장비·입력·뷰포트에서 순차 실행한다. 다른 GPU 브라우저나 인코딩을 동시에 돌린 표본은 비교 자료에서 구분한다. 수치가 좋아져도 한 번의 실행으로 인과 효과나 모든 기기의 향상을 확정하지 않는다.

## 실패 복구와 품질 경로

다음 항목은 정상 실행 뒤에 한 번씩 의도적으로 발생시켜 본다.

- [ ] 영상 404·디코딩 실패·자동 재생 거부에서 기본 표면이 남고 재시도가 무한 반복되지 않는다.
- [ ] 굴절·반사 캡처 실패 뒤 renderer 상태가 복원되고 대체 표현이 남는다.
- [ ] 탭 숨김·Work/Contact·대화상자에서 불필요한 렌더와 영상 재생이 멈춘다.
- [ ] 중지·재개 시 선택 각도와 영상 재생 위치가 기대한 정책대로 유지된다.
- [ ] WebGL context loss 뒤 준비를 다시 하고 오래된 콜백은 무시한다.
- [ ] 언마운트에서 texture·geometry·material·target·이벤트·프레임 콜백을 해제한다.
- [ ] 처음부터 reduced motion 또는 WebGL 미지원이어도 핵심 문구·탐색·프로젝트 정보에 접근할 수 있다.

효과를 줄이는 순서는 제품마다 정한다. AETHER는 모바일·소프트웨어에서 입자 예산과 추가 캡처를 줄이고, 일부 영상·광선 효과를 생략했다. 같은 모양의 반사를 제공하지 않는 경로는 그렇게 기록한다. 데스크톱 화면을 모바일 크기로 실행한 검사를 실기기 검증으로 표시하지 않는다.

## 채택과 되돌림 기준

아래는 다음 프로젝트에서 사용할 권장 기준이며 자동화된 정책은 아니다.

- 새 효과가 탐색·입력·복귀·실패 대체 화면을 깨뜨리면 효과를 비활성화하거나 변경을 되돌린다. 시각적 완성도보다 기존 흐름 복구를 먼저 한다.
- 대표 장면의 긴 프레임이 늘거나 품질이 계속 내려가면 같은 조건으로 재측정한다. 원인이 분리되지 않았으면 기능 단위로 끄거나 이전 버전을 유지한다. 평균 FPS 하나로 승인하지 않는다.
- 확인하지 않은 기기에서만 생길 수 있는 문제를 ‘없음’으로 처리하지 않는다. 지원 대상 실기기 확인이 끝나기 전에는 해당 경로의 검증을 대기로 남긴다.

효과·준비 코드·검증 자료를 읽을 수 있는 단위로 커밋한다. 어떤 변경을 되돌렸을 때 어떤 표현이 사라지는지 설명할 수 있어야 한다. 원본 자료와 측정값은 수정 후에도 남겨 비교 기준을 보존한다.

## AETHER 측정의 적용 범위

실제 Safari/iOS와 저사양 모바일의 장시간 발열 성능은 미검증이다. PR #16 챔버 변경은 RTX 2060 SUPER·Chromium ANGLE D3D11·1440×900·DPR 1에서 버전별 한 번 왕복 측정했다. 하강 최대 draw는 217에서 226으로 늘었다. 후속 PR #18 표본은 [별도 실행 기록](../scene-continuity.md)에 있다.

24개 경로 기준점, 40×28 흐름 격자, 512×512 반사 타깃, 특정 progress와 월드 높이는 이 프로젝트에서 선택한 값이다. 다음 프로젝트의 화면 길이·카메라·모델 크기·기기에 맞춰 다시 정하고, 위 순서로 확인한다.
