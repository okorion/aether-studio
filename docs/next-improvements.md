# 다음 개선 우선순위

PR #15의 독립 첫 진입 3회에서 최장 RAF 간격은 모두 16.8ms였고 33.5ms 초과는 없었다. 같은 규격의 VP8과 보이지 않는 영역의 캡처 생략을 적용한 결과다. 원인 분리·전체 왕복·겹침 비용은 [첫 모니터 성능 보고서](monitor-transition-performance.md), 구현 변천은 [시각적 이력](visual-history.md)에 기록했다. 아래는 아직 완료하지 않은 후속 작업이다.

| 우선순위 | 확인한 사실·한계 | 다음 작업 | 완료 판단 기준 |
| --- | --- | --- | --- |
| **1 · 실제 Safari/iOS와 저사양 기기 검증** | 최종 증거는 RTX 2060 SUPER·Chromium·ANGLE D3D11·1440×900·DPR 1이다. 실제 iOS Safari·저사양 GPU·장시간 발열은 미검증이다. 지원 조회를 조작한 MP4 선택 검사도 실제 기기 결과는 아니다. | 실제 기기에서 전체 왕복, 첫 영상 진입, 자동 재생·실패 대체 표현, 가로·세로 전환, 백그라운드 복귀, 모션 감소와 컨텍스트 복구를 확인한다. | 기기·OS·브라우저·DPR·코덱을 기록하고 전환 누락·영상 정지·복귀 실패가 없어야 한다. RAF·GPU 시간·품질·메모리·발열 경향을 따로 보고한다. |
| **2 · 겹침 구간의 최대 GPU 부하 줄이기** | 전체 평균 GL 호출은 약 4% 감소했지만 하강 겹침 최대 217 draw는 유지된다. 겹침 GPU p95와 최댓값은 일관되게 줄지 않았다. | 실제로 보이는 모니터·리액터·물 반사가 겹치는 구간의 GPU 병목을 나누고 재질 묶기·캡처 주기·LOD를 하나씩 비교한다. | 같은 카메라·영상 위상·입력에서 굴절·반사·O·체인·경계를 보존한다. 목표 기기의 겹침 GPU p95·최댓값이 반복 감소하고 재진입에 팝인이나 오래된 배경이 없어야 한다. |
| **3 · 근접 표면 품질 개선** | 512px 물 반사와 절차적 파편은 가까이에서 해상도·실루엣 한계가 남는다. 이번 변경에서 모델·전체 렌더 품질은 낮추지 않았다. | 실제 기기의 성능 예산을 정한 뒤 근접 파편 실루엣·표면 거칠기·수면 미세 반사를 보강하고 필요한 곳에만 비용을 쓴다. | 바닥 통과·역스크롤의 깜박임·경계 틈·입자 가림 회귀가 없어야 한다. 근접 품질 전후 캡처와 같은 조건의 비용을 함께 비교한다. |

**권장 순서는 1 → 2 → 3**이다. 현재 데스크톱의 긴 첫 진입 프레임을 계속 미해결로 취급하지 않고 다른 실제 기기로 결과가 이어지는지 먼저 확인한다. 단순히 모든 입자 수·해상도를 낮추는 변경은 기본안으로 삼지 않는다.

PR #10의 33.5ms 초과 간격 **8→1**, 셰이더 링크 **33→0**과 PR #11·#13의 약 83ms 잔여 프레임은 당시 결과로 보존한다. 측정 조건이 다른 역사 수치를 합쳐 누적 개선율로 계산하지 않는다. [PR #10](transition-performance.md) · [PR #11](spatial-transitions.md#실제-검증과-성능) · [PR #13](scene-occlusion-light.md#전환-성능과-한계)
