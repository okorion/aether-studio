# 한국어 기술 블로그 편집

기술 블로그 원고·캡션·도식에 적용한다. 지원 문서나 제품 UI에는 자동 적용하지 않는다. 사용자가 지정한 말투와 원문 보존 범위를 우선한다.

## 먼저 읽을 자료

- 대상 원고 전체와 그림 안의 모든 문구를 읽는다. 코드·수치·링크·그림도 편집 범위에 포함해 목록을 만든다.
- 사용자의 글이 있으면 관련 글 2~3편에서 도입 방식, 문장 길이, 말투, 기술 설명 깊이를 확인한다. 표본의 경험을 새 글의 경험으로 옮기지 않는다.
- 구현 근거, 측정 조건, 실제 캡처와 개념도를 구분한다. 원인이 미확정이면 그 상태를 유지한다.

## 본문 편집

1. 어떤 조작·환경에서 무엇이 어긋났는지로 시작한다. 상투적인 문제 제기나 기술의 중요성 소개는 덜어낸다.
2. 대상과 동작을 붙여 쓴다. ‘구조적 정합성을 확보했다’보다 ‘리본을 링의 부모 그룹 아래로 옮겼다’처럼 쓴다.
3. 한 문장에 하나의 관찰·행동·결과를 담는다. 길이 제한에 맞추느라 조건이나 예외를 지우지 않는다.
4. 첫 가설, 비교, 수정 순서를 실제 기록대로 쓴다. 처음부터 원인을 알고 있었던 것처럼 바꾸지 않는다.
5. ‘A가 아니라 B’, 질문 뒤 즉답, 세 항목 나열, 굵은 소제목, 교훈형 결론을 문단마다 반복하지 않는다. 실제 비교가 필요한 문장에는 남긴다.
6. ‘중요한 것은’, ‘단순히 ~을 넘어’, ‘이를 통해’ 같은 연결어는 뒤 문장을 직접 시작할 수 있으면 뺀다. 금칙어 치환만으로 편집을 끝내지 않는다.
7. 해결·결과·배운 점에서 같은 사실을 반복하지 않는다. 미해결 문제와 검증 한계는 관련 결과 옆이나 글 끝 한 곳에 모은다.
8. 작성자의 감정·실수·기억·개인 소유권을 만들어 넣지 않는다. AI 활용 사실을 지우거나 사람의 단독 작업으로 바꾸지 않는다.

말투는 대상 글에 맞춘다. 회고의 ‘했다’체와 안내의 ‘한다’체를 문맥에 따라 사용하되 이유 없이 존댓말과 오가지 않는다. 낯선 용어는 첫 사용에서 풀고 이후에는 같은 명칭을 쓴다.

## 그림과 캡션

- 그림의 주제목과 박스·축 제목은 명사형으로 끝낸다. 예: ‘링·리본의 부모 좌표계’, ‘DPR 중복 적용과 렌더 타깃 크기’.
- ‘확인해야 한다’, ‘달랐다’, ‘중요한 이유’ 같은 교훈·문장형 제목을 대상·현상·구조의 이름으로 바꾼다. 모든 제목에 기계적으로 ‘방법’이나 ‘분석’을 붙이지 않는다.
- 내부 문구는 짧은 항목명이나 직접적인 설명으로 쓴다. 단위·조건·미확인 범위는 유지한다.
- 캡션에 실제 화면·개념도·측정 재시각화와 필요한 비교 조건을 표시한다. 정지 화면을 성능 측정으로 설명하지 않는다.
- 원본 크기와 본문에 삽입한 크기를 모두 본다. 잘림·겹침·작은 글씨는 문구 축약 또는 배치 조정으로 고친다.

## 검수와 보관

원본은 보존하고 개정본을 별도 버전으로 만든다. 다음을 차례로 확인한다.

1. 사실: 코드 차이, 숫자·단위·측정 조건, 확정되지 않은 원인, 경험 주체.
2. 문장: 도입부터 끝까지 다시 읽으며 반복·번역투·추상적 판단을 제거한다. 자동 검사 경고는 문맥으로 판단한다.
3. 그림: 내부 텍스트 목록, 명사형 제목, 글자 영역과 실제 렌더.
4. 배포 파일: 원고와 게시용 본문 동일성, 링크·이미지·모바일 줄바꿈, ZIP과 SHA-256.

결과에는 수정 범위, 대표 전후 문장, 검수 결과와 남은 수동 작업을 남긴다. ‘AI 확률 0%’ 같은 탐지 점수나 자연스러움 보장을 사용하지 않는다. 외부 서비스에 원문을 올리거나 블로그에 게시하는 행동은 이 스킬의 편집 범위에 포함되지 않는다.
