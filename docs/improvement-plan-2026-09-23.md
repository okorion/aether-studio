# 개선 요구사항과 작업 순서 · 2026-09-23

이 문서는 개선 요구사항과 단계별 작업 상태를 기록한다. 현재 동작은 [장면과 입력 구조](architecture.md), 기존 검증 과제는 [후속 검증과 개선](next-improvements.md)을 함께 읽는다. 1단계 문서 PR 뒤 2단계 초기 로딩을 구현했다. 결과와 검증 한계는 [초기 로딩 진행률](loading-progress.md)에 기록했다. 3단계 본 컬럼 꽃 군집과 4단계 리액터 입자 동선을 구현했다. 5단계 챔버 조명·수면·잔해를 구현했다. 6~8단계는 아직 구현하지 않았다.

기준 소스는 `6e302ed`다. 이 계획을 정리하면서 Active Theory의 현재 화면을 새로 관찰하지는 않았다. AT와의 일치 여부, 영상의 반복 방식, 빛과 입자의 연결은 아직 검증하지 않았다.

## 공통 기준

- [Active Theory](https://activetheory.net/)를 AT로 부른다. 각 시각 작업 전에 해당 구간의 정지 화면, 정·역스크롤, 포인터 이동, 필요하면 클릭과 복귀를 직접 관찰한다. 관찰 날짜·URL·뷰포트·구간과 캡처 또는 짧은 영상의 위치를 해당 작업 기록에 남긴다.
- 관찰한 동작과 구현 방식에 대한 추정을 구분한다. 반복 여부를 확인하지 못한 영상은 비반복 영상이라고 단정하지 않는다. 접근하지 못한 경우에는 확인하지 못한 항목을 남기고 AT 재현 완료로 보고하지 않는다.
- 화면 구성과 움직임을 참고하되, AT의 소스·로고·영상·모델을 앱 자산으로 복제하지 않는다. 기존 생성 자산이나 사용 권한을 확인한 자산을 쓴다.
- [장면 용어집](scene-glossary.md)의 본 컬럼, 리액터·리액터 챔버, 스케일 패널, 상단·하단 포레스트 명칭을 사용한다.
- 스크롤에 따른 위치·형상은 같은 스크롤 위치에서 복원한다. 역스크롤 복원은 영상 프레임이나 수면의 시간 애니메이션까지 되감는다는 뜻은 아니다.
- 모션 정지·운영체제 모션 축소, 작은 화면, WebGL 대체 화면, 탭 숨김·복귀와 자원 해제를 유지한다. 관련 범위에서 검사하고, 실기기에서 확인하지 않은 결과는 별도로 표시한다.

## 1. README

개인 사이드 프로젝트의 의도, 볼거리, 조작법과 로컬 실행을 중심으로 소개한다. 개발 파일 목록과 검사 상세는 기존 개발 문서로 연결한다. 현재 화면과 예정 기능, 과거 캡처를 구분한다.

공개 기여를 받는다는 선언이나 새 라이선스를 추가하지 않는다. GitHub About의 `Interactive 3D`, topics, 공개 범위와 홈페이지 설정은 그대로 둔다.

## 2. 초기 로딩

실제 준비 상태와 연결된 진행률을 표시하고, 로딩 모션은 AT를 관찰해 구성한다.

추천 구현 기준은 첫 화면을 표시하는 데 필요한 모듈·필수 자원·셰이더와 GPU 준비·첫 프레임 준비를 단계로 구분하는 것이다. 완료 이벤트를 기준으로 진행률을 올리고, 측정할 수 없는 세부 진행은 단계별 가중치로 표현한다. 가중치는 실제 초기화 경로를 읽은 뒤 정하며 바이트 다운로드 비율로 오인하게 설명하지 않는다.

시간만 지나면 증가하는 가짜 진행률을 쓰지 않는다. 첫 프레임을 표시할 준비가 끝나기 전에 100%를 표시하지 않는다. 후속 씬의 지연 로딩 영상을 모두 기다리도록 바꾸지 않는다. 기존의 숨은 씬 셰이더 준비는 첫 진입 멈춤을 줄이기 위한 것이므로 로딩 표시를 위해 임의로 제거하지 않는다.

완료 기준: 차가운 캐시·재방문에서 진행률이 실제 준비와 연결되고, 준비 실패·WebGL 미지원 시 무한 로딩 없이 기존 대체 화면으로 이어진다. 취소된 초기화가 새 화면의 준비 상태를 덮지 않으며 모션 축소에서도 상태를 읽을 수 있다.

## 3. 본 컬럼 꽃 파티클과 회전

본 컬럼 양쪽에 입자 무리가 꽃 형상을 이루도록 한다. 개별 입자의 모양을 꽃 아이콘으로 바꾸라는 뜻은 아니다. 형상·배치·움직임은 AT에서 관찰한다.

아래로 스크롤할 때 주변 입자 무리가 화면에서 본 컬럼과 같은 반시계 방향으로 보이도록 수정한다. 카메라 회전과 월드 회전을 함께 확인해 부호 변경만으로 결과를 단정하지 않는다. 상대 속도는 AT를 참고하되 파악하기 어렵다면 차이가 커서 산만하지 않도록 조정한다. 속도의 정확한 일치보다 방향과 안정적인 시각 흐름을 우선한다.

완료 기준: 같은 카메라·스크롤 조건의 영상에서 두 대상의 회전 방향이 같고, 역스크롤에서도 일관된다. 꽃 무리가 양쪽에서 읽히며 모니터를 지나치게 가리지 않는다.

## 4. 리액터 입자 동선

입자가 장치 상단의 원형 개구부 위치에 모여 있다가 아래로 내려오며 O를 이룬다. 개구부와 관계없는 나선에서 시작하지 않는다. AT를 보고 `개구부에 모임 → 하강 → O 형성`에 적절한 스크롤 구간을 배정한다.

완료 기준: 천장 구멍과 입자의 출발 위치가 같은 공간으로 보인다. 중간에 스크롤을 멈추거나 빠르게 왕복해도 위치가 튀지 않고, 역스크롤하면 같은 동선을 되돌아간다. 기존 리액터 포인터 반응을 확인한다.

## 5. 리액터 챔버 분위기

전체적으로 어둡게 하고, 장치 상단의 원형 개구부에서 빛이 들어와 이전 씬과 이어지는 느낌을 만든다. 4번의 입자 출발점과 같은 개구부를 기준으로 한다.

수면은 완전히 고요하지 않게 흐르게 한다. 흐름의 방향·세기와 파괴된 구조물의 배치는 AT를 관찰해 정한다. 어두운 환경에서도 장치·수면·잔해를 구별할 수 있게 한다.

완료 기준: 입자와 빛의 출발 위치가 공간 구조와 맞고, 수면 흐름이 정지 상태에서도 보인다. 천장 차폐, 수면 반사와 인접 씬 전환에 회귀가 없는지 확인한다.

## 6. 모니터 영상과 인터랙션

AT의 영상 표현, 호버·포인터 이동·클릭 반응과 전환을 최대한 비슷하게 구성한다. 관찰한 입력부터 전환·닫기·복귀까지를 기록한 뒤 구현한다. 실제 콘텐츠는 프로젝트에서 사용할 수 있는 자산으로 구성한다.

현재는 모니터 클릭으로 프로젝트 상세 dialog를 열고 Work에서도 같은 프로젝트를 선택한다. 새 URL 라우팅 여부는 아직 확정하지 않았다. AT 관찰 후 필요한 전환 방식과 기존 탐색의 연결을 정하며, 외부 사이트나 무관한 페이지를 임의로 목적지에 추가하지 않는다.

완료 기준: 호버·클릭·드래그를 구분하고 상세 화면에서 닫기·Escape·포커스 복귀가 동작한다. URL을 바꾸는 구현이면 뒤로 가기·직접 진입도 확인한다. 영상 로드 실패, 정지·복귀와 작은 화면을 확인한다.

## 7. 스케일 패널

자동 파동은 7초마다 한 번 발생한다. 발생 지점부터 표면 끝까지의 전파 시간은 고정 3초다. `발생 간격 7초`와 `전파 시간 3초`를 독립된 설정값으로 두고, 전파 시간을 주기에서 빼서 계산하지 않는다. 기존의 작은 후속 박동을 별도의 두 번째 파동으로 남기지 않는다.

포인터 주변의 작은 범위에서 반응이 시작돼 바깥으로 파동이 진행되도록 한다. AT를 참고해 최초 반경·최대 반경·감쇠 시간을 조정한다. 현재 화면에서 약 70개 파편에 해당하는 범위라는 설명은 시각적 참고치이며 개수를 고정하는 요구가 아니다. 작은 움직임에 표면 전체가 즉시 반응하지 않게 한다.

작은 비누방울 같은 입자가 우주의 별처럼 부유하도록 추가한다. AT의 크기·밀도·움직임을 참고하고, 패널의 파동과 입력 반응을 가리지 않게 한다.

완료 기준: 자동 파동의 발생 간격과 전파 시간을 각각 확인한다. 자동 파동과 마우스 반응이 겹쳐도 과도하게 뒤집히지 않고, 포인터 이탈 뒤 남은 반응이 감쇠한다. 동일 뷰포트의 입력 영상으로 반응 범위를 비교한다.

## 8. 포레스트 경계

상단·하단 포레스트가 다른 씬으로 전환되는 경계에서, 포레스트 쪽에 낮은 식물 형상의 입자를 촘촘히 배치하고 입자·안개를 늘린다. 경계에서 떨어진 영역의 밀도와 분위기는 현재와 비슷하게 유지한다.

식물·입자의 포인터 반응, 배경 영상의 재생 방식, 빛이 안개처럼 퍼지며 입자에 영향을 주는 표현은 AT를 반드시 관찰한다. 과거 회상처럼 흐릿하고 몽환적인 화면을 목표로 한다. 하나의 비반복 영상이라는 해석은 관찰 전 가설이며 확정하지 않는다. 빛의 영향이 색·밝기 변화인지 움직임 변화인지도 구분해 기록한다.

완료 기준: 양쪽 경계 모두 밀도 변화가 자연스럽고, 인접 기계 씬으로 식물이나 포인터 효과가 새지 않는다. 배경 영상 실패 시에도 전환이 유지된다. 입자·안개·영상이 겹치는 구간의 프레임 비용을 기존 상태와 비교한다.

## 검증과 다음 작업 인계

각 구현 PR은 lint, typecheck, build와 변경 흐름에 필요한 테스트를 실행한다. 자동 검사 외에 같은 뷰포트·카메라·스크롤·입력 조건의 전후 화면을 비교한다. 회전·파동·하강·전환은 짧은 영상 또는 연속 프레임으로 확인한다. PR의 `시각적 변경`에는 대상·변경 전·변경 후·판단 포인트 표를 사용한다. 실제 캡처와 개념 이미지를 구분한다.

문서만 바꾸는 1번은 링크·명령·문체·Markdown 렌더를 확인하고, 앱 화면 변경이 없음을 PR에 명시한다. 후속 PR은 관찰 근거·선택한 값·실행한 검사·남은 한계를 기록하고 이 문서의 해당 상태를 갱신한다. 마지막 시각 작업 후에는 자원 변경을 반영해 초기 로딩의 진행률과 첫 화면 표시도 다시 확인한다.
