# 3D 장면 사이로 이전 오브젝트가 새어 나왔다

리액터 챔버에서 아래층으로 내려가면 스케일 패널이 나타난다. 그런데 스케일 패널의 천장 아래에 위층 리액터의 부품과 잔해가 보였다. 마지막 포레스트가 열리기 전에는 링 일부가 먼저 튀어나왔다.

장면을 잘 배치하는 것과, 전환 중 보이면 안 되는 것을 가리는 것은 다른 작업이었다. 이번에는 2D 페이지처럼 넘어가는 경계, 실제 3D 바닥과 천장, 그 사이로 남아야 하는 빛을 나눠 처리했다.

## 같은 경계를 쓰지 않으면 한 장면처럼 넘어가지 않는다

상단 포레스트에서 소개 문구가 나오고, 문구 앞에는 큰 3D 링이 남고, 아래에서는 본 컬럼과 모니터가 들어와야 했다. 각 요소가 따로 사라지면 단순한 장면 교체로 보였다.

현재는 스크롤 위치에서 전환 경계를 한 번 계산한다. 포레스트, 문구 평면, 링, 본 컬럼, 모니터가 그 값을 공유한다. 모니터에서 리액터로, 스케일 패널에서 하단 포레스트로 넘어가는 경계도 같은 방식이다.

3D 물체를 이미지로 바꾸는 것은 아니다. 각 표면의 픽셀이 화면 어디에 있는지 계산해서, 사선 경계 밖이면 그리지 않는다.

```glsl
// 개념을 줄인 예시: clip 좌표를 화면 UV로 바꿔 공통 경계를 읽는다.
vec2 screen = clipPosition.xy / clipPosition.w * 0.5 + 0.5;
float edge = screen.y - (screen.x - 0.5) * 0.20;

if (edge > upper || edge < lower) discard;
```

실제 구현에는 경계가 자로 그은 선처럼 보이지 않도록 작은 노이즈와 좁은 완화 영역을 넣었다. 경계 기준은 viewport UV다. 메인 화면과 저해상도 렌더 타깃에서 픽셀 수가 달라도 같은 위치를 가리켜야 하기 때문이다.

소개 문구는 카메라를 향하는 평면으로 만들었다. 평면처럼 보이면서도 깊이 검사를 유지해 링은 문구 앞에, 다음 장면은 정해진 경계 안에 들어오도록 했다.

![공유 전환 경계와 3D 층별 차폐의 역할](../images/layers.png)

*설명용 도식. 화면의 사선 마스크, 실제 깊이를 기록하는 천장, 아래층 진입 후 위층 구조를 숨기는 조건을 구분했다.*

## 투명하게 만들었다고 뒤가 보이는 것은 아니었다

초기 하단 장면에서는 희미한 기둥이 링을 가리는 일이 있었다. 투명한 재질도 깊이를 기록할 수 있기 때문이다.

색은 거의 보이지 않는데 깊이 버퍼에는 ‘여기에 물체가 있다’고 남으면, 뒤쪽 물체가 그 자리에 그려지지 않을 수 있다. `transparent`와 `opacity`만 보고 판단하면 놓치기 쉬웠다.

역할을 나눴다. 분위기를 만드는 투명 장식은 불필요한 깊이를 쓰지 않도록 하고, 위층을 실제로 가려야 하는 천장은 불투명한 별도 재질로 깊이를 기록하게 했다.

화면 경계로 숨기는 픽셀은 깊이 쓰기 전에 `discard`한다. 단순히 최종 alpha만 0으로 만드는 방식과 다른 점이다.

공통 마스크를 기존 재질에 붙일 때는 `onBeforeCompile`도 덮어쓰지 않았다. 본 컬럼의 미세 표면 효과처럼 이미 사용하던 훅을 먼저 호출한 뒤 경계를 추가하고, 프로그램 캐시 키에도 두 효과를 반영했다. 경계를 추가한 뒤 재질의 다른 효과가 조용히 사라지는 일을 막기 위한 보강이다.

## 천장을 닫아도 아래로 튀어나온 부품은 가려지지 않았다

모니터에서 리액터로 전환할 때는 입자가 O로 모이는 과정이 너무 일찍 보였다. 당시 천장은 투명했고, 리액터 상단 소켓도 속이 비어 있었다.

여기에 불투명한 천장과 막힌 상단 덮개를 추가했다. 수렴 입자에도 모니터 퇴장 경계를 적용해, 들어오는 리액터 챔버 영역 안에서만 나타나게 했다. 위로 나가는 모니터 영역에 새 모양이 먼저 보이지 않도록 했다.

그다음은 아래층이었다. 스케일 패널 위에 넓은 천장을 두어도 위층의 긴 기둥과 잔해가 남았다.

원인은 다른 곳에 있었다. 일부 모델이 바닥 아래까지 실제로 돌출돼 있었다. 카메라도 바닥 아래에 있으니, 같은 쪽에 있는 돌출 부분을 위쪽 천장이 가릴 수는 없다.

![수정 전, 스케일 패널 천장 아래로 보이는 위층 구조](../../screenshots/occlusion-v13/before/scroll-785.jpg)

![수정 후, 위층 구조는 가리고 천장 빛을 유지한 화면](../../screenshots/occlusion-v13/after/scroll-785.jpg)

*같은 1440×900, 78.5% 위치의 PR #13 당시 실제 화면이다. 위층 구조의 노출과 천장 구성을 비교한다. 조명 영상 재생 시간은 같지 않아 밝기 차이를 개선율로 읽을 수는 없다.*

아래층에 진입했는지는 스크롤 비율만으로 판단하지 않고 실제 카메라의 월드 높이를 읽었다.

```ts
// 현재 처리의 핵심을 줄인 예시
const inLowerRoom = eyeHeight <= floorHeight - 0.03

chamber.visible = deviceWeight > 0.001 && !inLowerRoom && deviceCoverage
ruins.update(inLowerRoom ? 0 : architectureWeight)
architectureBars.visible = !inLowerRoom
```

카메라가 아래층에 도착하면 위층 리액터와 잔해·긴 지지대를 숨긴다. 위로 돌아갈 때는 원래 상태를 복원한다. 멀리 있는 단순한 벽은 아래 공간의 배경으로 남긴다.

위층의 물체를 숨긴다고 빛까지 없앨 필요는 없다. 천장의 물결빛과 공유 영상 조명은 따로 유지했다. 물체의 가시성과 광원의 표현을 같은 visible 값으로 묶지 않은 이유다.

## 받침과 천장은 독립된 숫자로 맞추고 있었다

리액터 받침은 바닥에서 약 0.485만큼 떠 있었다. 이후에는 상단 덮개와 천장 사이에 2.52의 간격이 남았다.

사진을 보며 각각의 위치를 조정해 온 결과였다. 닿아야 하는 면의 좌표를 공유하지 않으면 다른 부분을 수정할 때 다시 벌어질 수 있다.

받침은 윗면을 유지하고 아랫면을 실제 바닥보다 조금 낮게 연장했다. 바닥에도 굴곡이 있으므로 중심 y만 같게 하는 대신 geometry의 범위를 확인했다.

천장은 덮개의 윗면에서 계산했다.

```ts
// 실제 구현의 접점 계산
const capThickness = 0.26
const capCentreY = 3.15
const ceilingY = capCentreY + capThickness * 0.5
const ceilingThickness = 0.18
```

덮개 윗면이 3.28이면 천장의 아랫면도 3.28이다. 얇은 천장판은 그 위에 놓인다. 케이블 끝과 가로보 높이도 같은 기준을 사용했다.

![천장 접점을 맞추기 전 리액터 챔버](../../screenshots/chamber-art/before/scroll-675.jpg)

![덮개와 천장판의 접점을 맞춘 리액터 챔버](../../screenshots/chamber-art/after/scroll-675.jpg)

*같은 67.5% 위치, 1440×900·DPR 1, 동일한 시계 진행과 영상 2초 정지 상태의 PR #16 전후 화면이다. 접점과 주변 설비의 배치 변경을 함께 보여준다.*

검사에서는 실제 월드 bounding box로 받침의 하단, 바닥의 최솟값·최댓값, 덮개 상단과 천장 하단을 읽었다. 깊이 차폐도 별도로 확인했다. 장치가 물리 시뮬레이션으로 바닥에 안착하는 구현은 아니다. 정해진 모델 배치에서 접점이 맞는지 검증한 것이다.

## 넓힌 바닥이 화면을 검은 띠처럼 덮었다

바닥을 카메라 쪽으로 넓히자 공간은 좋아졌지만, 카메라가 바닥 높이를 통과할 때 두께가 화면을 크게 가렸다. 가까운 면이 near plane 주변에서 확대되어 보이는 문제였다.

바닥의 위 표면, 두께를 표현하는 slab, 아래쪽 천장 면을 분리했다. 카메라가 가까워지는 순간에는 두께와 위 표면을 완화하고 아래쪽 천장과 빛은 유지한다. 물은 바닥 위에서만 보이게 했다.

바닥 전체를 일괄적으로 꺼 버리면 전환이 쉬워 보일 수 있지만, 위층과 아래층을 연결하는 표면도 사라진다. 현재 구현은 카메라 높이와 각 표면의 역할을 따로 본다.

이 처리 뒤에도 캡처만으로 끝내지 않고 아래층에 들어갔다가 다시 올라오는 입력을 확인했다. 한 방향에서 자연스러워도 역방향에서 잔해가 늦게 돌아오거나 천장이 먼저 사라질 수 있기 때문이다.

## 마지막 링도 포레스트와 같은 경계 안에 있어야 했다

스케일 패널에서 하단 포레스트로 넘어가는 사선은 맞았지만, 링 일부가 경계 양쪽에 보였다. 포레스트와 심벌이 서로 다른 가림 기준을 사용하고 있었다.

후반 링·내부 O·리본 트레일에 모두 같은 `forestEntry` 경계를 적용했다. 포레스트가 열린 영역부터 심벌이 나타나고, 아직 남아 있는 스케일 패널 화면 안에서는 보이지 않는다.

이는 링 전체를 특정 progress에서 갑자기 켜는 처리와 다르다. 같은 3D 링이지만 화면에 드러난 부분만 그린다. 따라서 순방향과 역방향에서 같은 경계를 되짚을 수 있다.

## 물과 영상빛은 어디까지 구현했나

공간의 밝기 변화는 처음에는 절차적인 광원 변화로 만들었다. 이후 공개된 원본 실행 코드와 셰이더를 조사하면서, 하나의 영상 텍스처를 여러 표면과 조명 표현에서 공유하는 구조를 확인했다. AETHER에는 자체 제작 영상을 연결했다. 원본 영상·모델·코드를 런타임에 복사하지 않았다.

영상은 화면 전체에 똑같이 덮지 않고 월드 위치로 샘플링한다. 같은 순간에도 가까운 잎과 먼 가지, 리액터의 다른 면이 영상의 다른 색을 받는다. 포레스트 뒤 곡면 배경과 부드러운 광선 면도 같은 텍스처를 참조한다.

이 광선은 깊이 검사를 하는 면을 겹쳐 만든 표현이다. 원본의 볼류메트릭 샘플링과 같은 구현이라고 주장할 수는 없다.

물은 작은 파동으로 표면 법선과 반사 샘플 위치를 바꾼다. 비스듬히 볼수록 반사가 강해지는 Fresnel 항을 사용하고, 얕은 물의 색과 가장자리 투명도를 합성한다. 데스크톱은 기존 512×512 평면 반사 타깃 하나를 재사용한다. 모바일·소프트웨어 프로파일은 실제 장면 반사 캡처를 생략하고 물결과 절차적인 빛을 사용한다.

이후 밝고 선명한 영상 패턴이 포레스트의 분위기를 깨는 문제가 있어 어두운 사틴 반사 영상으로 교체했다. 리액터 챔버도 중앙을 비우고 양측 설비를 배치했다. 이는 기능 오류를 고친 것과 구분되는 시각 설계 개선이다. 추가 설비 때문에 일부 전환의 draw 수는 증가했으며, 같은 작업을 성능 개선으로 기록하지 않았다.

스케일 패널의 동심원 소용돌이도 별도로 제거했다. 타일 중심으로부터의 반지름을 위상으로 쓰던 파동을 낮은 주파수의 방향성 굴곡으로 바꾸고, 겹쳐 있던 나선 입자를 제거했다. 포인터 주변의 들림과 반사 반응은 유지했다.

## 가림 검사는 색과 깊이를 같이 봤다

숨겨진 곳에 색이 보이지 않는 것만 확인하면 투명 깊이 문제를 놓칠 수 있다. 서로 다른 표준·커스텀 셰이더에 같은 경계를 적용하고, 화면비와 타깃 크기를 바꿔 숨겨진 색과 깊이가 모두 남지 않는지 검사했다.

접점은 geometry의 월드 범위로, 아래층 진입은 실제 카메라 높이로, 최종 앞뒤 순서는 실행 화면으로 확인했다. 조명은 같은 위치에서 시간 간격을 두고 촬영했지만, 영상만의 기여를 분리한 실험은 아니다.

여기서 정리한 가림과 공간 배치 이후에도 최초 모니터 진입의 긴 프레임은 따로 남아 있었다. 표면이 안 보이는 것과 그 표면을 위해 렌더 패스가 실행되지 않는 것도 서로 다르다. 그 비용은 다음 렌더링·성능 글에서 이어서 다룬다.
