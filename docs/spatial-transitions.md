# 지하층 전환과 공간에 투사되는 빛

2026-09-22. 모니터에서 지하 장치로, 장치에서 바닥 아래 비늘로, 비늘에서 하부 숲으로 내려가는 세 경계를 다듬었습니다. 장면이 교체되는 인상을 줄이도록 공간의 높이와 가림을 유지하고, 바닥의 반사와 숲·장치 표면의 시간에 따른 빛 변화를 연결했습니다.

## 원본 조사에서 확인한 범위

[Active Theory](https://activetheory.net/)의 실제 화면과 [공개 실행 스크립트](https://activetheory.net/assets/js/app.1780406240914.js)를 조사했습니다. 아래 내용은 조사 시점의 구조에 관한 관찰이며, 원본 소스나 영상·모델을 AETHER 런타임에 복사하지 않았습니다.

| 확인 대상 | 원본에서 확인한 구조 | 이번 구현에 적용한 판단 |
| --- | --- | --- |
| 공유 영상 조명 | `ViewController`에서 `reel.mp4`의 `VideoTexture`를 공유 | 자체 제작 영상 하나를 여러 재질에서 공유하고 디코더를 추가로 복제하지 않음 |
| 숲·로고 입자의 빛 | `TreeFBR`와 `LogoParticle` 셰이더의 `tVideo`를 월드 XZ 좌표로 샘플링하고 Overlay·SoftLight 계열 합성에 사용 | 화면 전체 색을 바꾸는 대신 월드 위치에 따라 다른 색과 밝기를 표면에 투사 |
| 바닥·벽 | JPG lightmap과 mirror 사용 | 자체 생성 표면과 단일 평면 반사에 물결·천장 빛 무늬를 결합 |
| 물의 영상 사용 | 물 셰이더의 직접 영상 샘플링 부분은 주석 처리된 상태 | 물에는 영상을 직접 넣지 않고 반사와 절차적 물결·빛 무늬를 사용 |
| 평면 소개 wrapper | 정확한 2D wrapper 클래스명은 확인하지 못함 | 특정 원본 클래스나 동일한 내부 구현을 주장하지 않고, 화면에서 관찰한 가림과 이동을 자체 평면 레이어로 구성 |

## 세 경계의 공간 연결

아래 `p`는 AETHER 홈 전체 스크롤의 정규화 값입니다. 원본 사이트의 내부 progress와 일치한다는 의미는 아닙니다.

| 경계 | 배치와 전환 | 확인할 화면 |
| --- | --- | --- |
| 모니터 → 지하 장치 | `p=.61~.69`의 사선 경계로 모니터와 척추가 위로 빠지고 장치가 드러납니다. 카메라 궤도 잠금과 모니터의 프로젝트 선택 동작은 유지합니다. | 66%에서 두 공간이 겹칠 때의 앞뒤 순서 |
| 장치 → 비늘 | 장치 `Y=-40.4`, 바닥 `Y=-44.1`, 비늘 중심 `Y=-48`은 각각 월드 공간에 고정됩니다. 카메라가 바닥 위에서 아래로 지나가며 장치는 위층에 남습니다. | 72%, 76.5%, 78.5%에서 바닥 위·통과·아래의 연속성 |
| 비늘 → 하부 숲 | `p=.855~.925`의 사선 경계로 고정된 하부 숲이 드러납니다. 위쪽 비늘과 문구가 빠져나가고, 숲의 상부 가지와 고사리가 먼저 보인 뒤 링 주위 공간으로 내려갑니다. | 89%, 91.5%에서 위쪽 수관과 중앙 링의 가림 |

바닥은 **22×26 월드 단위**의 유한한 면과 얇은 두께로 구성했습니다. 카메라가 두께 안을 통과할 때 큰 검은 띠가 화면을 덮지 않도록 눈높이에 가까운 두께와 표면을 완화합니다. 바닥 위의 얕은 물은 시선 각도에 따른 반사, 서로 다른 방향의 작은 물결, 가장자리 감쇠를 셰이더에서 계산합니다. 아래쪽에서는 같은 바닥이 천장이 되고, 불규칙한 세포 경계 형태의 움직이는 빛 무늬가 보입니다.

데스크톱 GPU에서는 기존 **512×512 평면 반사 타깃 하나**를 물 표면에 재사용합니다. 물이나 천장 빛을 위한 추가 장면 캡처는 없습니다. 모바일과 소프트웨어 렌더러는 반사 캡처를 생략하고 절차적 표면과 빛을 표시합니다.

## 위쪽 숲과 시간에 따른 조명

상·하부 숲이 공유하는 geometry에서 전체 잎·미세 입자 예산의 **24%**를 local Y 약 7~12의 상부 수관에 배분했습니다. 기존 줄기에 비대칭 아치를 연결하고 길게 휜 고사리와 매달린 덩굴을 붙였습니다. 데스크톱 총 60,000개, 모바일 18,000개, 소프트웨어 렌더러 4,500개는 유지하며, 잎 mesh와 미세 입자 모두 같은 비율로 상부에 분산합니다. 가지는 기존 instancing에 포함되므로 draw가 늘지 않습니다. 두 숲의 월드 기준점과 중앙 링의 빈 공간도 유지합니다.

빛은 월드 좌표에 고정된 넓고 불규칙한 영역으로 나뉩니다. 청록·금·보라 계열이 서로 다른 느린 위상으로 이동하며, 가까운 잎과 뒤쪽 줄기, 장치의 다른 면에 서로 다른 색과 밝기를 만듭니다. 10~20초 동안 한 위치에 머물러 변화를 관찰할 수 있습니다. 포인터 주변의 밝기·변형은 이 시간 변화와 별도 입력입니다.

공유 조명 영상은 수식으로 직접 제작한 크롬 유체 영상의 저해상도 파생본인 [`light-projection.mp4`](../public/media/light-projection.mp4)입니다. **218,188바이트, 256×160, 12fps, 10초 무음 루프**이며 모니터용 두 영상과 별도의 디코더 하나를 사용합니다. 준비된 영상의 색을 월드 XZ 기반 좌표로 읽어 선형 색 공간으로 변환한 뒤 기존 절차적 빛에 낮은 세기로 섞습니다. 영상이 없는 동안에도 절차적 조명은 유지합니다. [출처·재생성·미디어 수명](light-projection-media.md)

## 실제 검증과 성능

로컬 lint·typecheck·build와 **전체 55개 테스트**가 재시도 없이 통과했습니다. 마스크 테스트는 서로 다른 두 셰이더와 화면비·타깃 크기 3종에서 총 12상태를 그려, 숨겨진 색과 깊이가 새지 않는지 확인합니다. 새 영상의 지연 다운로드·정지·재개·404 이후 기본 조명 유지도 검사했습니다. 이후 초기 샘플링 준비 보강은 관련 수명·준비 테스트로 다시 확인했습니다.

실제 GPU 검수는 기본 여정 16지점, 모바일 6지점, 고정 카메라에서 4초 차이의 조명 3쌍, 실제 휠로 하부 세 전환 왕복, 조명 재생 중 컨텍스트 손실·복구를 포함합니다. 기록된 브라우저 오류는 0건입니다. [전체 이미지 목록과 SHA-256](screenshots/spatial/manifest.json), [실제 입력·복구 기록](screenshots/spatial/verification.json)을 보존했습니다. 캡처 소스는 `b9b61fc`이며, 이후 `09bcdcf`는 첫 화면 전의 조명 샘플링 준비만 보강합니다.
