# 3D 인터랙션 페이지에서 화면과 동작이 어긋났을 때

AETHER의 첫 화면부터 영상 모니터, 지하 공간, 마지막 포레스트까지 구현하며 마주한 문제를 모았다. 정지 화면에서는 맞아 보였지만 드래그하면 연결부가 벌어졌고, 아래층에서는 위층 모델이 새어 나왔다. 처음 스크롤할 때만 길게 멈추는 문제도 있었다.

문제를 한 번에 해결한 과정은 아니다. 카메라 경로를 고친 뒤에도 영상 초기화 지연은 남았고, draw를 줄였지만 GPU 시간은 같은 비율로 줄지 않았다. 그런 구분을 남기기 위해 글을 주제별로 나눴다.

## 이 기록의 기준

**기본 6편과 이슈 색인은 2026-09-22, PR #17 병합 커밋 `cfee1e1036f50482fd24e2e2c3239c67b1d2bb4d`까지를 다룬 역사 스냅샷이다.** 이후 변경으로 운영 화면이 달라져도 당시 실패·측정·캡처를 새 결과로 바꾸지 않는다. 후속 구현은 별도 부록에서 그 기준과 검증을 기록한다.

실제로 재현된 결함, 코드·실패 주입 검사로 막은 위험, 시각 설계 개선을 구분했다. 코드에 방어 로직이 있다는 이유만으로 과거에 운영 장애가 발생했다고 쓰지 않았다. 같은 문제를 여러 차례 수정한 경우에는 당시 남았던 증상도 함께 적었다.

코드 생성과 수정에는 AI를 사용했다. 본문은 그 과정에 남은 코드·리뷰·검증 자료를 읽어 정리했으며, 확인되지 않은 개인의 설계·구현 경험을 추가하지 않았다. 별도 프로젝트에서 작성한 개인 Velog의 절두체 컬링 사례는 문체 참고이며 AETHER에서 다시 발생한 사건으로 합치지 않았다.

## 이미지와 숫자는 이렇게 읽는다

본문의 JPG·PNG·GIF 중 `docs/screenshots/`에서 가져온 파일은 당시 실행 화면이다. `images/`의 그림은 설명용 도식 또는 저장된 측정 기록을 바탕으로 만든 차트다. 실제 화면으로 만든 것처럼 표시하지 않았다.

전후 사진에는 가능한 범위에서 같은 뷰포트·스크롤·카메라·입력을 사용했다. 영상과 조명 시각이 다른 비교는 캡션에 남겼다. GIF는 실제 입력 중 캡처한 화면을 묶은 요약이며, 재생 간격이 앱의 FPS를 뜻하지 않는다. 입자 위치·정지·복귀는 별도의 행렬 또는 픽셀 검사로 확인했다.

성능 수치는 실험마다 조건이 다르다. 첫 GPU 준비, 이후 영상 진입, 최신 챔버 변경의 값을 한 통제 실험이나 누적 개선율로 합치지 않는다. RAF 간격은 GPU 실행 시간과 다르며, draw 감소도 FPS·전력 개선율이 아니다.

이 기록의 최신 챔버 표본에서 하강 최대 draw는 226이었다. 특정 데스크톱의 왕복 표본이며 모든 기기의 상한은 아니다. 실제 Safari/iOS·저사양 모바일·장시간 발열과 메모리는 별도 검증이 남아 있다.

## 보관하고 게시하는 방법

문서 원본과 실제 이미지 파일은 [공개 저장소](https://github.com/okorion/aether-studio)에 함께 보관한다. 코드·측정과 같은 버전으로 관리할 수 있고 이후 수정도 비교하기 쉽기 때문에 이 저장 방식을 기본으로 삼았다.

이동 가능한 보관본은 **이미지 내장 HTML**, **Markdown과 실제 이미지 파일을 담은 ZIP**으로 구성한다. HTML은 이미지가 파일 안에 들어 있으므로 파일 하나만 옮겨도 본문과 그림을 읽을 수 있다. Markdown은 이미지 파일을 함께 보관해야 한다. 생성 규격과 사용법은 [보관 묶음 안내](README.md)에 있다.

Velog에는 게시용 Markdown을 사용자가 직접 게시한다. 본문은 같고, 이미지·근거 주소만 공개 저장소의 고정 커밋 URL로 바꾼다. Velog 에디터에 붙인 뒤 이미지가 보이는지 확인하고, 직접 이미지 업로드를 선호하면 ZIP 안의 실제 파일을 올려 주소를 바꿀 수 있다. 이 문서화 작업에서 계정에 자동 게시하지 않는다.
